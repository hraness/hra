## HRA Codex Cloud routing

- Keep the root coordinator and integration owner on the caller-selected model. Treat every Codex Cloud worker as `cloud-default`; never claim that a local model or reasoning setting carried into Cloud.
- Route only bounded repository work that starts from an exact pushed branch, is Linux-container compatible, has one branch owner, and needs no private local input, authenticated browser, interactive auth, 2FA, Mac-native capability, signing, release, deployment, production readback or mutation, agent-phase secret, or agent-phase network access.
- Use a hybrid route when portable implementation can run in Cloud but an authenticated, provider, Mac, signing, or production proof must remain local. Keep repository final gates authoritative.
- Qualify the source with `$hra-cloud-efficiency` and its online route check immediately before dispatch. Use one attempt by default and documented `codex cloud` commands only. Do not automate private provider endpoints.
- Never run the current Cloud CLI from a repository directory. Use the installed private launch guard so its diagnostics stay in an exact disposable mode-0700 scratch directory and prompts travel over stdin.
- Do not hold a local compute lease while waiting for Cloud. One owner reviews the Cloud diff, integrates it into the expected clean tree, and runs the required exact-tree final gate.
- Keep HRA hosted or Convex operations separate. Use `$hra-local-efficiency` for local scheduling, capability lanes, validation receipts, CI ref audits, and cleanup.
