# Contents

- `index.md` routes maintained product knowledge.
- `plans/` contains current implementation and release plans with evidence and progress.
- `notes/` contains reusable concepts that remain true outside one execution phase.

# Guidelines

- Markdown is authoritative. Generated search or graph data must be rebuildable and must not replace authored decisions.
- A plan records scope, decisions, phases, acceptance evidence, risks, and execution state. Update it as the implementation changes.
- A note contains a reusable claim with enough evidence to verify it. Do not promote speculation as current knowledge.
- Keep product-local facts here. Link public primary sources directly and avoid private repository or machine provenance.
- Use stable titles, YAML frontmatter, and relative Markdown links.
