# Oh memory and session civilization

## Outcome

Every newly bound Codex or Claude Code session receives one static HRA preamble and a closed provider-native tool surface. Such a session can inspect bounded provider-neutral state for another session in the same project, send an attributable queued message, or steer a supported active turn. It can remember into its own expiring Oh working authority, query that working authority together with a durable project canonical authority, explain results, and explicitly share nominated memory through a destination-owned compare-and-swap adoption. Retired Devin sessions remain historical local data only; they cannot execute or participate in peer coordination.

Oh remains agent agnostic. HRA consumes a stable `@hraness/oh/memory` contract, owns project and session bindings, implements Oh's operation-sync transport over client-encrypted hosted storage, and never puts an HRA identity provider or HRA-specific transport into Oh.

## Constraints

- Preserve HRA's operating-system-user local custody model. Provider callbacks and a narrow Claude bridge provide application attribution, not hostile same-user process isolation. Peer credentials, PID ancestry, environment markers, and a second readable bearer do not create that boundary.
- Use append-only, transactional, restart-safe HRA migrations. Do not rewrite a released schema.
- Derive the calling session from the provider callback or daemon-minted bridge binding. Model input never selects its actor, account, project, store, locator, rules, clock, operation ID, sync credential, or purge authority.
- Peer coordination is enabled by default within the actor's exact current project. Keep a per-session `off | inspect | coordinate` revocation policy. Cross-project and cross-machine session addressing, autonomous session creation, approval resolution, stop, switch, archive, rename, and attachment transfer are out of scope.
- Treat peer messages and memory text as untrusted user data, never system text or approval. The target session's existing approval and autorespond policy remains the only approval authority.
- Persist mutating peer evidence before provider dispatch. Store bounded identifiers, policy decisions, causal links, and content digests, not message or transcript bodies. Bounded inspect reads remain non-mutating.
- Retain complete peer replay and causal detail for at least seven days, then prune only closed terminal subgraphs on a later new admission. Pin active actor and target turns, unsettled effects, unresolved evidence, and every recursively required parent and root. Preserve queue `peer_session` attribution after an eligible terminal or resolved action link is detached.
- Use a peer-specific causal limit of eight. Do not reuse Work DAG depth or manufacture implicit Work membership. Conservatively union all peer origins attached to the actor turn when checking cycles.
- Keep per-session working memory's existing 30-day lifecycle and fork semantics. Add one physical canonical database per project with no TTL. Serialize all memory operations for one project in one coordinator, with canonical adoption and sync under that same owner, while keeping physical project authorities separate.
- Sync canonical project authorities only. Client-side encryption, operation verification, fast-forward-only settlement, explicit divergence, bounded quotas, retention, erasure, and recovery evidence are mandatory. No Turso credential path is added to HRA; Oh's existing alternate transport is sufficient independence evidence.
- Existing personal conversations are adopted without a new HRA host-tool binding. Codex resume cannot install dynamic tools, and Claude's existing prompt snapshot may ignore a later append. Do not persist capability digests as evidence for an unproved provider effect. Preserve the original conversation, ordinary session custody, scheduled work, and owner-facing memory; newly created or explicit provider-switch replacement threads admit the full capability.
- Static preamble bytes and the host-tool manifest are versioned and digest-bound to each bound Codex or Claude Code session. They contain no live lists, clocks, heads, paths, credentials, or dynamic state. Bound resume and a switch into Codex or Claude Code retain or admit one exact version. Active provider selection is limited to Codex and Claude Code.
- Workers own focused validation. The integration owner runs `bun run check` on each converged repository tree through the required HRA host scheduler, then follows each repository's documented review, release, deployment, and production-readback flow.

7. The local release exposes the closed provider-native HRA host-tool manifest to capability-bound Codex and Claude Code sessions, plus an owner-facing `hra memory` command group governed by established session and project authority rather than model-tool installation. Owner memory therefore also works for adopted sessions without a host-tool binding. Both surfaces call the same `HraMemoryPort` coordinator and share the same bounded value schemas; neither exposes an Oh locator, arbitrary CRUD, caller-chosen rules, purge authority, or head acceptance.
8. One HRA coordinator serializes all memory work per project, including per-session working writes and composite reads. This deliberately trades same-project memory concurrency for one canonical-head, recovery, and project-change boundary. Different projects remain independent.
9. HRA never synthesizes or blindly retries a canonical replacement after a share conflict. Oh offers a host-only replacement primitive bound to an exact prior record digest, but HRA returns conflict evidence and keeps that primitive unreachable until the owner explicitly authorizes durable canonical overwrite semantics.
10. Exact mutation replay is finite, while active-page attestation evidence has reference-bounded lifetime. Terminal submissions remain for at least 30 days, are pruned only before a later admission, and are capped at 10,000 rows per project. Unsettled recovery evidence is never pruned. Compact evidence remains independently for every currently referenced working or canonical page and is collected after replacement or proven working-authority purge. Tool receipts expose `idempotencyRetainedUntil` rather than implying permanent same-key replay.
11. Local fork admission uses Oh's stable 32 MiB memory-lane limit and 8,192-record limit. The combined SQLite database and WAL ceiling is 512 MiB. HRA configures a transactional page limit so a capacity failure rolls back before an operation ID can become durable.
12. Same-profile provider switches preserve the account-bound working authority. Cross-account switches fail before provider effects once memory exists; because sessions acquire memory at start, this is a deliberate compatibility restriction pending explicit authorization for cross-account memory transfer.
13. A canonical divergence freeze is sticky and visible through `hra memory status`. The local release has no thaw, canonical rollover, project-memory erasure, or project-removal path; those operations require an exact separately authorized custody design.
14. Peer-action replay is finite without making recovery evidence disposable. HRA admits at most 120 new actions per project per rolling hour, keeps full action and causal rows for at least seven days, and caps the project at 25,000 rows. The seven-day rate envelope is 20,160 rows, leaving 4,840 rows of protected headroom. Admission-triggered cleanup removes only old terminal closed subgraphs; active-turn, unsettled, unresolved-evidence, parent, and root pins win over cleanup, and capacity then fails closed. Eligible queue rows retain their durable `peer_session` actor after the detailed action reference is detached.
15. A canonical authority receives a random portable space identity before HRA creates or opens its physical Oh database. The local project digest selects only the private directory. New rows use identity contract 2, whose realm, authority ID, binding, and authority digest derive from the portable space rather than the machine-local project ID. Their physical lifecycle is monotonic: `reserved` before open, then `initialized` only after exact verification or terminal `rejected` after a failed first verification. A missing initialized database never becomes a fresh create, and deleting or replacing a rejected artifact never thaws its identity. A crash-left legacy database may be adopted only when custody and Oh verification prove its head, binding, and every non-anchor table exactly empty; its contract-1 identity then becomes immutable. Every nonempty, replaced, or mismatched orphan fails closed. Pre-portable rows otherwise retain their exact existing physical identity; a same-version development migration may add the explicit identity fields only after validating the old table shape and every stored digest.
16. Oh exposes replication only through a host-only canonical capability, never through `OhStoreV1` or the memory agent facade. Bundle import is one atomic compare-and-swap over the full interval, and Oh, not HRA, owns exact search-materialization verification. HRA applies a universal precommit canonical-operation byte ceiling small enough for one encrypted hosted row; working remembers retain the larger local memory-page bound, while an oversized share is a known no-effect refusal.
17. Hosted sync is split around the network boundary. Under the project tail, HRA opens the one canonical authority, captures an exact pinned bundle and durable intent, and closes it. A single daemon-wide scheduler performs network I/O without holding the project tail, SQLite connection, or process-custody lease. HRA then reacquires the project tail, reopens the same authority, and settles only after revalidating the project generation, portable binding, local head, remote observation, and durable intent. A sync fence blocks canonical mutation while an intent is unresolved but does not block working writes, local status, or working-only reads.
18. Hosted storage has an owner-scoped `memorySpaces` configuration row and immutable owner-scoped `memoryOperations` rows. The server compares only sequence and a purpose-separated keyed head token; an encrypted head proof lets an enrolled client reconstruct the raw Oh head. Exact replay after the remote has advanced compares every submitted row and acknowledges only the exact submitted tail. A missing configured remote head means erased or recovery-required and never auto-creates a replacement space.
19. Project registry payload v1 stays byte-strict. Memory supervision uses a separately encrypted `memorySummaryEnvelope` and groups devices by portable space identity. It reports disagreement, stale publishers, enrollment gaps, local-only state, and frozen conflicts explicitly; it never chooses a canonical head by max sequence or last-writer-wins.
20. Generic memory status exposes the identity contract and bounded authority, binding, and head digests, not the raw portable space ID. Only explicit owner-controlled hosted-space create, list, and attach flows may reveal or accept that identifier.
21. The canonical replication seam requires an explicit control-plane head on every call; omission is a programming error and never means “trust the physical database.” A split-phase caller may inspect a proven descendant only to reconcile it, must compare the returned physical head with its durable authority before network I/O, and may not sync an unexplained local advance. Oh's core conflict, integrity, dependency, and profile errors use native immutable cross-entrypoint brands so HRA does not classify packaged conflicts by mutable error names.
22. An attached canonical mutation requires the hosted synchronizer to be present and the local, last-exchange, and remote heads to be exactly converged. Missing sync capability is recovery-required, not permission to write locally and upload later.
23. Memory supervision is an auxiliary background snapshot with its own hosted mutation and revision. It authenticates complete-or-bounded coverage for spaces, peer policies, and actions; derives peer references from both a stable local namespace and the publishing device; excludes inactive publishers; and cannot suppress the ordinary registry heartbeat or command path when snapshotting, encryption, quota, or publication fails.
24. Browser device registration must preserve the durable device class through the supported registration contract. It fails closed if that contract is unavailable instead of retrying a classless legacy registration that could weaken daemon-only authority.
25. Canonical-memory cryptographic helpers zeroize every owned account-key, space-key, decrypted plaintext, proof, descriptor, operation, and oversized-buffer copy on success and failure while leaving caller-owned input buffers untouched.
26. Provider switching uses the existing HRA mutation, target, seed-intent, seed-result, and release receipts. Preserve exact provider-account, personal-runtime, and Claude-process authority, deliver the seed before releasing the source, and add the admitted host-capability binding to that state machine. Remove the unshipped parallel journal: it lacked those authorities and left production dispatch and recovery using different records.
27. Every host-tool call and response notification requires explicit provider and managed/personal provenance from its runtime adapter. Peer effects join their prepared action to the existing send or steer mutation immediately before dispatch, and use the same account-wide compact-projection recovery fence as owner commands.
28. Established-session authority, including an exact personal-Claude binding on macOS, governs native host tools, automation callbacks, and provider facts. Codex profile login state alone does not establish or revoke Claude authority. A completed atomic provider-switch receipt may reconcile a lost local acknowledgement without repeating any provider effect.
29. Local memory submission recovery precedes daemon readiness; hosted recovery runs under one bounded background supervisor. Per-project retries preserve exact durable intents and isolate transient failures, while foreground canonical sharing remains fail-closed until convergence. Shutdown aborts and joins the supervisor before closing its local authorities.
30. A provider-originated host call must prove its exact live account generation, connection, thread, turn, call ID, and request digest again after authority-lock acquisition. Codex fences received turn and request invalidation before its serialized fact observers; Claude checks the stream client's active turn as well as the manager's retained binding. Receive-state capacity fails closed rather than forgetting a revoked turn. Admission is the linearization point, not a promise of retroactive cancellation after a later disconnect. Response acknowledgement requires an actual exact-call frame write, and stale completion may clear only its own retained call. Teardown never drains callbacks while holding locks they need.
31. Claude acceptance needs one source-only, one-shot capture alongside independent durable-state and provider-consumption evidence. A terminal memory submission retains its request and receipt digests but not the bridge call, connection, binding, or response-written completion. The earlier black-box-only approach therefore cannot prove the complete exact-call boundary. Restrict the typed capture to live-acceptance installations before any daemon effect, preserve ordinary production dispatch, and observe response-written only after the managed runtime has accepted the exact receipt and completed its call. No public flag, environment toggle, generic observer, persistent provider payload, or public memory-readback command is added. The real runner must independently match the committed nonce page and receipt, the same-turn assistant echo, and exact private teardown before producing passing evidence.

## Phase 1: Graduate Oh memory

- **Status:** Complete
- **Depends on:** none
- **Objective:** Publish a stable, HRA-independent two-authority memory API as `@hraness/oh/memory` v0.4.1.
- **Scope:** Keep `remember`, named/paginated `query`, `explain`, and `nominate` on an agent-only object. Add a separate host object with serialized `advanceCanonical` and `adoptNomination`, including an optional bounded host-only exact-prior-record replacement claim. Make Oh verification prove exact search materialization. Retain the experimental subpath as a compatibility alias.
- **Out of scope:** HRA identity, HRA transport, automatic conflict merging, model-chosen canonical writes, and new persisted Oh wire bytes.
- **Approach:** Canonical advance proves same-head idempotence or exact reachable descent before swapping the captured lane. Adoption strictly reparses and re-exports a nomination from the bound working store, compares the exact canonical snapshot, and inserts all missing closure records in one CAS. A different digest conflicts by default. The host may replace only when every supplied claim names the exact canonical prior record digest and nominated key; the operation identity binds the prior head and exact changes. HRA v1 supplies no replacement claims. Old explanations survive rollover; continuations remain bound to exact source heads.
- **Acceptance criteria:** Stable and experimental imports resolve to the same reviewed implementation; the agent object has no host/store/sync/purge handle; rollover rejects rollback/unreachable heads; verification rejects search documents or full-text rows that do not exactly materialize the verified live records; default adoption is dependency-complete, idempotent, all-or-nothing on conflicts, and resistant to a forged self-digested nomination; optional replacement validates every claim and cannot alias a different parent or change set under one operation ID.
- **Validation:** `bun test ./src/memory.test.ts`; Node portable type/runtime tests; package smoke; `bun run check`; reviewed PR; annotated immutable v0.4.1 release; npm and GitHub artifact/provenance readback.

### Historical synthetic-fixture admission

The message-sanitization and memory-summary refusal tests deliberately construct synthetic absolute user paths. Their current source now joins path components, preserving the runtime inputs without literal private-path shapes. Complete-history scanning must still examine each original addition, its integration merge, and its removal. Neither rewriting immutable history nor exempting a path prefix, file, or complete patch is allowed.

| History-only implementation | Admission evidence | Maintenance cost |
| --- | --- | --- |
| Replace each selected exact fragment after verifying the full commit ID, patch SHA-256, and occurrence counts | Exact immutable patch bytes; every other byte remains subject to both policies | One fixed record per reviewed addition, merge, or removal and at most two bounded replacements |
| Parse patch hunks before the same digest-bound replacements | The same immutable evidence, plus redundant hunk-location verification | A patch parser and additional failure cases |

Use the first implementation in `scripts/check-package.ts`. Pin full object IDs and the patch's diff algorithm, context, ordering, prefixes, quoting, indicators, submodule form, and external-attribute policy instead of inheriting object-count abbreviations or local diff settings. Bind full and public patch digests independently: they differ when a reviewed commit also changes the lockfile. Each immutable record selects one or both of the two exact fixture fragments and requires exactly one occurrence of each selected fragment. A changed digest, swapped scan kind, different fixture, empty or duplicate selection, or changed occurrence count must refuse. General and current-tree public-text rules remain unchanged, and the complete-history gate still scans roots, deletions, merges, and every governed ref. Revisit this choice if Git's patch representation changes or an admitted commit is no longer in governed ancestry; do not refresh an admission merely to make a failing scan pass. Focused adversarial tests and the fresh complete-history package gate remain required.
