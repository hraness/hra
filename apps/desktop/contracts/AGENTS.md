# Guidelines

- Keep generated Codex types out of renderer imports; only HRA-owned contracts may cross the native bridge.
- Expose only stable public workspace/task/repository identifiers, path-free repository readiness, one pathless global folder display name and availability, bounded portable task data, and the HRA-owned chat-pane facade. Chat schemas may contain app-owned pane, turn, message, attachment-reference, and tool identifiers; optional schedule revision, RRULE, time zone, and next-run metadata; an independent bounded FIFO queue projection with complete editable user text; content-free routing evidence; bounded reasoning-summary and assistant-Markdown tails; provider-neutral tool categories; and product errors. Expose no pane-level model, effort, tier, or routing preference. Keep prompt features, matched text, selected folder paths, repository URLs/paths, private eligibility evidence, worktrees, provider identifiers, private interactions/runs, usage, model catalogs, compatibility diagnostics, full transcripts, tool commands, and tool output out of renderer schemas.
- Treat schedule instructions as transient configure-command input. A successful response and every durable renderer projection contain only normalized schedule metadata; removal clears it atomically under the pane revision fence.
- Parse every foreign value from `unknown` and preserve exhaustive discriminants for owned messages.
- Bound renderer-facing collections and payloads below the native transport ceilings. Use counts for destructive previews and snapshot invalidation for oversized snapshot-recoverable state.
- Keep task pages and details out of the global runtime snapshot. Read each local or recovery workspace root through one correlated atomic projection command, continue its list by cursor plus immutable continuation revision, and page an oversized serialized dispatch response without changing its representation mid-transfer.
- Treat Native transport sequence and each workspace's durable projection/event sequence as separate fields and concepts. A scoped task invalidation advances Native delivery order without putting task state in the account snapshot.
- Keep credential material, login IDs, authorization URLs, device codes, raw provider values, and human-in-the-loop answers outside snapshots, events, responses, diagnostics, and operation receipts. A strict app-owned message-ledger command may carry complete bounded user text plus opaque attachment references; its head-steer intent may fence only the app-owned active chat turn. It must never name a provider turn, thread, operation, path, or interaction authority. Queue text is private local pane state, not an operation receipt or diagnostic. A mutation-attempt start may carry the already-authorized portable intent transiently so the gateway can bind it; attempt responses and persisted journal metadata must not echo or retain that intent. The only recovery-material exception is one explicit user-initiated, size-bounded `sessionSyncRecoveryKit` response with a short expiry; it must never appear in a snapshot, event, receipt, diagnostic, or persisted renderer state.
- Keep the live attachment command surface image-only and path-free. Generic files fail before custody; preview responses carry only normalized `image/png` bytes for an exact pane, attachment, revision, and relationship.
- Expose an unresolved ambiguous message as one complete bounded read-only `deliveryOutcomeUnknown` receipt. Its only renderer mutation is terminal-only discard; never expose edit, retry, resume, or provider authority for that row.
- Return a pane mutation's live projection only for the exact applied revision. A recorded replay is a distinct content-free proof carrying only the pane, command kind, and applied revision; the renderer reads current pane state from its authoritative projection and never treats it as the historical effect.
- Treat contract changes as compatibility changes: update fixtures, reducers, and boundary tests in the same phase.
- Regenerate versioned protocol artifacts from the pinned binary; do not hand-edit generated files.
