# Guidelines

- Validate arguments and returns for every public and internal function. Parse browser, provider, and persisted foreign values from `unknown`; validate every stored external URL as credential-free HTTPS at this backend boundary.
- Reload mutable membership, grant, credential, agent, session, workspace, scope, and organization status in the final transaction before a protected write. Missing, foreign, and inaccessible human administration selectors must remain tenant-opaque `NOT_FOUND` results after current organization authorization.
- Derive organization and workspace IDs from loaded records. Start workspace reads from workspace-scoped indexes except the documented pre-authentication, scheduling, and integrity inverse locators; those exceptions must validate the complete tenant tuple before use. Organization disable/removal remains O(1), while every final human and agent gate rechecks organization status.
- Treat agent disablement and credential status as immediate authority. Cleanup projections may follow but must never delay revocation. Read secrets only from typed Convex environment variables and never persist or return bearer material.
- Commit protected state, its idempotency receipt, and the matching closed typed event in one mutation. Retry thrown contention only at the idempotent HTTP boundary with the same key, digest, and request ID; never retry a returned domain failure or weaken a quota.
- Keep `humanCommandReceipts` authoritative for command outcomes. Resolve the transient browser digest to a versioned HMAC bound to organization, workspace, principal, and source before the generic journal receives it. The hosted attempt journal stores only that HMAC, its non-secret key version, exact recovery identifiers, bounded state metadata, and a terminal summary. It must never store or return the browser digest, raw intent, human answers, transcript, provider data, or command result payloads.
- Configure one canonical 32-byte current fingerprint key and at most one distinct previous key. Retain the previous pair until all open rows under that version settle. Missing, malformed, half-configured, or prematurely retired key material fails closed; never silently re-key an open attempt.
- Never evict an open hosted mutation attempt. Reject prepare at the per-principal workspace/source capacity, read underlying pages in batches of at most 50, distinguish key or fingerprint collisions, and retain terminal rows without letting them block a later deliberate action. Prepared attempts may settle rejected or cancelled. Effect-started attempts may settle cancelled only when the caller has positive proof that the requested effect did not occur; otherwise keep the attempt open and ambiguous.
- Keep task record revision separate from review revision. Review-affecting graph or specification changes advance both, comments only append evidence, and a submission freezes the exact review revision. Submissions are a discriminated union with one pending variant and immutable accepted, rejected, and cancelled terminals under stable-agent four-eyes review.
- Enforce the full organization/workspace/task/agent/public-ID/fence/generation/deadline tuple on claimed-task operations. Freeze agent edits in review. Treat readiness and blocker counts as checked projections; disagreement fails closed and enqueues generation-checked repair rather than accepting compact state.
- Prove dependency and parent acyclicity within explicit node, edge, blocker, dependent, and depth bounds. Exhausted proof rejects the mutation. Preserve cancelled tasks, comments, events, dependency history, references, and terminal reasons; reopening starts a new lifecycle and repository removal is soft deletion.
- Never derive desktop readiness from `agentSessions`. Runner authority is fenced by installation, boot generation, contiguous heartbeat sequence, repository capability, claim, and tenant tuple; run updates must present the complete current tuple.
- Persist only the closed lifecycle/display run-event union. Reasoning summaries and assistant messages require bounded text; lifecycle and tool events reject it. Never accept raw reasoning, tool identity or arguments, commands, local paths, output, provider IDs, or arbitrary transcript/log payloads.
- Keep remote HITL to bounded provider-declared non-secret questions and one-shot managed-worktree file decisions. Store only the fixed-size sealed answer envelope; bind requests and settlements to current workspace/key, runner, boot, claim, fence, digest, expiry, and response revision. Delete ciphertext on acknowledgement or expiry, page oldest first, and treat the lifetime cap as terminal.
- Enforce active and lifetime task limits through the exact transactional workspace-usage row. Debit authenticated mutations after final authorization in the protected write transaction. Reactive human point reads stay authenticated, bounded, paginated, and non-debiting; the long-poll HTTP invalidation adapter alone has dedicated user-and-workspace admission limits so held actions remain bounded.
- Advance one ordered workspace projection watermark per visible semantic transaction. Persist one closed tenant-bound invalidation with that watermark, advance view continuations only for membership or order changes, and fence targeted patches to one exact Convex snapshot.
- Treat password, refresh, pairing, and scope-rotation material as untrusted. Keep raw migration claims out of mutation arguments and persistence; retain only bounded digests. Bind one password account to one preserved HRA user.
- Recheck the active user, organization membership, selected organization, and selected workspace for every authorization. An organization-only session cannot call workspace routes, and an exact workspace selection cannot cross into another workspace.
- Keep Web Crypto possession checks in actions or HTTP actions and database transitions in narrow mutations. Gate local fixtures behind the explicit fixture flag and exact Convex issuer/subject; they remain outside the versioned HTTP API.
- Reauthorize the active HRA human and current organization membership when issuing or consuming every suite proof. Bind the product, environment, HRA user, challenge, timestamps, key version, and suite account; reject replay mismatches and both-direction alias conflicts. Suite aliases are additive metadata and never authorize product membership, roles, workspaces, agents, credentials, sessions, or runners.
- Verify suite entitlement receipts with the web-owned HRA receipt verifier before a monotonic projection write. Select the one active issuance key with `SUITE_IDENTITY_RECEIPT_KEY_VERSION`, while keeping same-environment retired versions in the verification keyring until every at-most-five-minute proof and receipt expires. Expose freshness-tagged verified state for possible future gates, but do not gate an HRA capability in this integration.
- Order verified entitlement projections with the shared provider-revision and signed-receipt-issuance law. Persist issuance on new writes, retain the receipt digest for exact replay evidence, and use the optional field only to backfill pre-policy rows.
- Keep session sync content-blind and fail closed. The relay may store authenticated schedule metadata plus an opaque end-to-end-encrypted scheduled definition, but never its plaintext prompt or content; only an HRA device decrypts and enqueues it. Authenticate the exact HRA human, selected tenant/workspace, current membership, vault generation, membership epoch, device key, signed route/body/nonce/expiry, boot, mirror, writer, sequence, previous digest, and key epoch before mutation. Exact replay must be revision-, counter-, and scheduled-work-stable.
- Materialize snapshots from active heads and tombstones while counting unconsumed reservations against quota but omitting them from the visible page. Represent a revoked origin as the last accepted head plus a newer mirror-reset overlay; never revive its stream or writer fields.
- Derive presence only from server-observed heartbeats for devices in the current signed membership. Return only device ID and coarse connection state, force revoked devices offline, represent missing or invalid observations as unknown, and never let presence affect execution authority or local chat availability.
- Enforce event and compatibility-evidence ciphertext under one 64 MiB vault budget. Make bounded pruning atomically coherent across change rows, payload rows, entry counters, vault counters, and floor; partial safe progress may return a retryable result, while pinned or corrupt state fails closed without dangling references.
- Preserve `_generated/` as generated output. Regenerate it with local `convex dev` or `convex codegen`; do not hand-edit it.
