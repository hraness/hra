# HRA observation invariants

This registry covers the bounded status and watch surfaces. It names the proof that currently exists and keeps live evidence separate from deterministic evidence.

Evidence tiers:

- **Deterministic**: an automated test or static boundary proves the guarantee without a live Codex account.
- **Existing live**: the underlying provider or event behavior has live release evidence, but the new presentation surface may not have been exercised separately.
- **Unproved live**: no live claim is made. The deterministic contract remains the release gate.

| ID | Owner | Guarantee | Deterministic proof | Live evidence tier | Known limitation |
| --- | --- | --- | --- | --- | --- |
| OBS-001 | CLI entry point and `StateStore` | `hra status` produces a bounded local-only snapshot without starting or calling the daemon and without provider, cloud, browser, login, usage-refresh, recovery, or mutation work. Provider and cloud coverage are `not_attempted`; device counts are unknown rather than zero. | [`src/cli.test.ts`](src/cli.test.ts), “reads root status locally without daemon autostart or transport”; [`src/storage/state-store.test.ts`](src/storage/state-store.test.ts), “reads latest nonremoved account usage outcomes without leaking private root data” and “establishes each SQLite observation cut before assigning its observed time” | Unproved live | It has no global revision or cursor. Commits after the transaction establishes its snapshot cut, including concurrent commits while it remains open, are visible only on the next call. `fresh` means a direct uncached snapshot, not linearizability at the later observation timestamp. |
| OBS-002 | `StateStore` and daemon session status | Session status produces one typed provider-observation result, attempting a Codex app-server read only when local state makes it applicable, and then reads the session row, event cut, pending interactions, responses in flight, and queue axes in one SQLite read transaction. The local cut is schema-validated as complete and fresh. | [`src/storage/state-store.test.ts`](src/storage/state-store.test.ts), “reads one bounded local session observation with exact interaction and queue semantics”; [`src/daemon/service.test.ts`](src/daemon/service.test.ts), “exposes an atomic status cursor and wakes a bounded event tail without losing safe deltas” and “session status separates pending summaries from responses in flight and reports queue axes” | Existing live for provider status and event flow; v2 projection unproved live | The provider result precedes and is not transactionally atomic with the local SQLite cut. Its basis, generation, connection, coverage, and observed time remain separate evidence. |
| OBS-003 | Session event ledger and observer pump | The cursor returned by session status names the event cut read with the local snapshot. Status and event-page output accept only one canonical `hra1` wire envelope with a canonical base64url payload and 32-byte signature. Watch resumes through the existing signed-cursor event API. Every writable event-page read applies count, age, and byte retention before returning its snapshot. Retention, restore, and provider disconnect gaps remain explicit, including gap-only reads from idle or terminal sessions. Duplicate, skipped, cross-account, nonmonotonic, or false-restoration delivery within one observer run is rejected before cursor advancement. | [`src/daemon/service.test.ts`](src/daemon/service.test.ts), atomic status cursor, event-tail, idle and terminal retention, prior-epoch restore, and disconnect cases; [`src/storage/state-store.test.ts`](src/storage/state-store.test.ts), read-time age retention without a later append; [`src/domain/session-events.test.ts`](src/domain/session-events.test.ts), cursor-envelope, page, and cross-page continuity cases; [`src/cli/watch.test.ts`](src/cli/watch.test.ts), cursor advancement, malformed-response zero-output, exact-session pinning, continuity rejection, and transient reconnect cases | Existing live for the underlying event stream; `session watch` alias unproved live | The wire schema proves only canonical bounded framing. Cryptographic authority, cursor type, session binding, epoch, and sequence remain daemon verification responsibilities. A consumer restarting from its last durable checkpoint must deduplicate any replay across runs. The event ledger is not a complete wake source for every authority transition. |
| OBS-004 | Observation domain | Execution, attention, provider observation, pending count, response-in-flight count, and queue state remain independent. Attention is advisory and cannot replace the exact counts or revisions that determine the next operator action. | [`src/domain/observation.test.ts`](src/domain/observation.test.ts), advisory combination and torn-status cases; [`src/daemon/service.test.ts`](src/daemon/service.test.ts), mixed interaction and queue status case | Unproved live | Attention uses a closed precedence for display. New execution or interaction states require a reviewed schema and combination audit. |
| OBS-005 | Observation schemas and storage projection | Root status contains counts and at most 50 ID-and-revision action records and is at most 256 KiB. Session status contains at most 10 pending summaries. Root output excludes labels, emails, titles, notes, transcripts, payloads, paths, and queued text; session output excludes notes, provider thread IDs, raw provider turn IDs, and private interaction authority. Within status, event, and interaction observation output, every provider turn and item ID is a secret-keyed `opaque_v2_` alias; the public schemas reject every raw or malformed value. One durable local key keeps aliases coherent across those surfaces and daemon restarts without exposing a guessable digest of low-entropy input. If that key is missing after durable HRA state exists, daemon startup refuses to replace it and requires restoration of the original secret. | [`src/storage/state-store.test.ts`](src/storage/state-store.test.ts), privacy, malformed stored-v2, and maximum-attention fixtures; [`src/domain/observation.test.ts`](src/domain/observation.test.ts), serialized bound and truncation cases; [`src/domain/session-events.test.ts`](src/domain/session-events.test.ts), exact alias grammar and lossless keyed projection; [`src/daemon/service.test.ts`](src/daemon/service.test.ts), bounded session-status and cross-surface alias cases; [`src/daemon/session-event-cursor.test.ts`](src/daemon/session-event-cursor.test.ts), durable-key alias stability; [`src/daemon/streaming-redaction.test.ts`](src/daemon/streaming-redaction.test.ts), provider-identifier projection; [`src/cli.test.ts`](src/cli.test.ts), lost-key startup refusal | Unproved live | This registry does not claim that older non-observation command receipts or full session projection reads alias their provider identifiers. Session status intentionally includes a bounded credential-and-path-redacted title and bounded credential-and-path-redacted interaction summaries. Full details require explicit existing inspection commands. |
| OBS-006 | Shared session watch pump | Human watch and machine JSONL use one cursor pump. A page must finish writing before the cursor advances or the next page is fetched. New durable event bodies are at most 64 KiB. Public validation permits at most 146 additional bytes for projection of the two shortest private identifiers in a legacy row, and enforces the 512 KiB aggregate event-page bound before any output. `session events --follow` remains compatible. | [`src/cli/watch.test.ts`](src/cli/watch.test.ts), slow JSONL writer, human presenter drain, malformed-cursor and oversized-page zero-output cases; [`src/domain/session-events.test.ts`](src/domain/session-events.test.ts), exact durable, legacy-projection, and page byte boundaries; [`src/cli/parser.test.ts`](src/cli/parser.test.ts), watch syntax and compatibility cases; [`src/cli/shell.test.ts`](src/cli/shell.test.ts), shell alias and help cases | Unproved live for the alias; existing live for event follow | Slow output applies backpressure to that observer. It does not block provider event ingestion into SQLite, but it can make the observer lag and encounter a typed retention gap. |
| OBS-007 | Daemon provider adapter | Every session provider result names `codex_app_server`, whether its basis is a provider read or a local-state gate, the exact account process generation, observed time, coverage, freshness, and live connection evidence where one exists. Unbound, signed-out, terminal, and recovery states do not masquerade as live or imply an unperformed read. | [`src/daemon/service.test.ts`](src/daemon/service.test.ts), “reports explicit provider provenance for unbound, signed-out, quarantined, and terminal sessions”; [`src/domain/observation.test.ts`](src/domain/observation.test.ts), strict status parsing and basis consistency | Existing live for the pinned provider adapter; v2 projection unproved live | Freshness describes the stated basis. HRA does not claim a shared atomic revision across provider and SQLite state. |
| OBS-008 | CLI contract and research gate | No public `session wait` command exists until every supported predicate advances a per-session predicate revision in the same transaction as its authority change and waiter registration rechecks that revision before sleeping. Agents use status plus watch or bounded polling. | [`src/cli/parser.test.ts`](src/cli/parser.test.ts), help and unsupported-command cases; [`kb/plans/hra-v1.md`](kb/plans/hra-v1.md), “Research gate result (2026-08-26)” | Not applicable | Interaction admission, some execution and recovery transitions, and queue changes do not currently share one event transaction. Event sequence alone cannot prevent a lost wake. |
| OBS-009 | CLI parser, renderer, and daemon boundary | Observation commands do not accept an approval, answer, plugin, login, usage-refresh, recovery, or other mutation payload. Root guidance uses a closed intent bound to the exact public ID. Account and session guidance is inspection-only; interaction inspection also binds the observed revision. | [`src/domain/observation.test.ts`](src/domain/observation.test.ts), strict intent and status schemas; [`src/cli/render.test.ts`](src/cli/render.test.ts), closed root inspection commands; [`src/cli/parser.test.ts`](src/cli/parser.test.ts), strict root status and watch options | Unproved live | A later mutation remains a distinct explicit command and must re-read current authority. A stale root snapshot never renders an unfenced account-login cancellation or session-recovery mutation. |
| OBS-010 | Human watch interaction presenter | A complete current interaction record may render only decisions supported by its kind and current public display. File-change approval is never offered through HRA. A summary-only event notice renders the exact show command and no mutation command. Prepared or written responses never invite resubmission. Standalone human watch buffers at most 1 MiB of initial UTF-8 guidance and emits none of it until enumeration is complete; foreground-watch resumption retains only exact `(id, revision, state)` tuples and filters fresh pages incrementally. | [`src/cli/shell-live.test.ts`](src/cli/shell-live.test.ts), complete-decision, summary-only, response-in-flight, unsupported-file-approval, and incremental pending-page cases; [`src/cli.test.ts`](src/cli.test.ts), current-revision bootstrap, atomic bootstrap byte bound, event-notice, and foreground observer-ownership cases | Unproved live | Event notices intentionally lack resolution authority. Agents must show or list the current interaction before deciding. A human bootstrap that exceeds its bound fails with no partial stdout and directs the operator to bounded interaction pages. |
| OBS-011 | Session-list response boundary | JSON session listings project one strict public item DTO, remove notes and provider thread or turn identifiers, bind every scoped row to the resolved account, and require an exact account-ID selector to match the response. Unknown response fields never cross the JSON boundary. | [`src/cli/render.test.ts`](src/cli/render.test.ts), exact-account mismatch, cross-account row, private-field stripping, and signed-out continuation cases | Unproved live | Session titles and public project IDs remain intentional list fields. A mutable account label resolves inside the daemon, so the response supplies the immutable account ID used for later continuation. |

## Session facts-memory invariants

| ID | Owner | Guarantee | Deterministic proof | Live evidence tier | Known limitation |
| --- | --- | --- | --- | --- | --- |
| MEM-001 | Facts-memory domain and control store | One binding is derived from the exact account/session pair. HRA persists only bounded lifecycle authority, opaque hashes, exact public heads and receipt digests, checkpoints, state, expiry, and cleanup evidence. No facts, semantic payloads, rules, projections, credentials, paths, or raw handles enter the control schema. | [`src/domain/facts-memory.test.ts`](src/domain/facts-memory.test.ts), stable binding and receipt cases; [`src/daemon/facts-memory-lifecycle.test.ts`](src/daemon/facts-memory-lifecycle.test.ts), authority-only schema and cross-owner cases | Unproved live | Oh v0.2.0 is release-verified at `89fb133`; its strict adapter mapping is not active yet. |
| MEM-002 | Facts-memory lifecycle coordinator | A lost create response is reconciled by exact inspection before another idempotent create dispatch. Resume rejects handle or receipt drift and head regression or equivocation. Fork records one exact parent binding and head and preserves that checkpoint across replay. | [`src/daemon/facts-memory-lifecycle.test.ts`](src/daemon/facts-memory-lifecycle.test.ts), create/finalize race, replay, cross-owner, exact fork, and partial-cleanup cases | Unproved live | HRA has no public session-fork command. This is a host integration seam for a future explicit session branch operation, not new provider-session semantics. |
| MEM-003 | Local facts-memory broker | One future Oh SQLite store and all of its WAL, SHM, and caches stay beneath one host-derived canonical session directory. Cleanup quiesces, validates, quarantines, and removes the complete tree before returning a purge receipt. Path traversal, symlinks, linked files, and inexact parent checkpoints fail closed. | [`src/storage/local-facts-memory-broker.test.ts`](src/storage/local-facts-memory-broker.test.ts), complete sidecar cleanup, crash-left quarantine retry, symlink, traversal, and checkpoint cases | Unproved live | Path custody is not a sandbox against another process running as the same operating-system user. Backups, filesystem snapshots, and storage media may retain prior bytes. |
| MEM-004 | HRA service boundary | Session start and provider resume reconcile memory; terminal status archives it; explicit abandon proves cleanup before releasing local recovery; a bounded expiry sweep runs at admitted command boundaries. No facts-memory command, store selector, path, rules, or purge capability exists in `LocalCommand`. | [`src/daemon/service.test.ts`](src/daemon/service.test.ts), start/resume/archive/expiry hook, abandon ordering, and command-union absence cases | Unproved live | Service construction remains optional until the exact Oh adapter is released. Existing Codex cancellation and recovery semantics are unchanged. |

The focused observation gate is:

```sh
bun test src/domain/observation.test.ts src/domain/session-events.test.ts src/domain/interactions.test.ts src/storage/state-store.test.ts src/daemon/session-event-cursor.test.ts src/daemon/streaming-redaction.test.ts src/daemon/service.test.ts src/cli/parser.test.ts src/cli/shell.test.ts src/cli/watch.test.ts src/cli/render.test.ts src/cli/shell-live.test.ts src/cli.test.ts --isolate --max-concurrency=1
```

The focused facts-memory gate is:

```sh
bun test src/domain/facts-memory.test.ts src/daemon/facts-memory-lifecycle.test.ts src/storage/local-facts-memory-broker.test.ts src/daemon/service.test.ts --isolate --max-concurrency=1
```

Before delivery, run the complete repository gate:

```sh
bun run check
```

The existing live acceptance harness remains in [`scripts/live-acceptance-scenario.ts`](scripts/live-acceptance-scenario.ts) and [`docs/live-acceptance.md`](docs/live-acceptance.md). It is not treated as proof of the new root status, session-status v2 projection, or watch alias until those exact surfaces are added to a live run.
